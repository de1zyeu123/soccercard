# 《足球命格》产品动线设计（v2 · 逻辑校验版）

> 本版在原稿基础上做了三件事：①逐屏校验用户故事逻辑；②修复闭环与分支上的逻辑缺口；③把每屏「谁、在哪、看到什么、能做什么、去哪、为什么」写清楚，让设计/开发/文案任何一方单独看都能懂。
> 文末「第 12 章 逻辑校验与待决项」汇总了本次发现的问题与处理建议。

**产物**：逐屏动线 + 各屏文案位。不含文案库、结果命名、视觉方案、技术实现细节。

**分两期**：
- **Phase 1（先上）**：单人测试 + 单人卡传播闭环。
- **Phase 2（紧跟）**：拼队玩法——队长发起、成员加入、生成赛前 11 人合影。
- Phase 1 的设计**必须为 Phase 2 预留接口**（见第 6 章）。

> ⚠️ **硬性前置依赖｜结果持久化**
> Phase 1 即便不做账号，也**必须**把每次测试结果存一份、绑定一个唯一 ID。
> 这是 Phase 2 拼队的命脉——拼队靠「球队链接归集成员结果」运转。若 Phase 1 做成纯无状态（测完即走、不存），Phase 2 会直接卡死、需推翻重做。
> 此项非「优化」，而是 Phase 2 能否成立的前提。详见第 6 章。

## Phase 1 · 单人测试

### 1. 动线总览

两条入口，在「输入 → 揭晓 → 结果页 → 传播」处合流。

```
   【A 普通入口】              【B 朋友落地页 · 主力】
   A1 强钩子页               B1 朋友结果落地页
   钩子+示例+承诺            朋友结果+一句挑衅
        │ 测我的                  │ 测我的
        └──────────┬──────────────┘
                   ▼  合流
        ① 输入流程（点选为主）
        性别·生日·城市·球风·位置
                   ▼
        ② 揭晓动效 1.5–2.5s
                   ▼
        ③ 结果页（大结果名+角色图+金句）
           主动作：保存图片
           预留位：组一支队（Phase 2 点亮）
              │
              ▼
        ④ 传播：保存图 + 附带回流链接，发群/朋友圈
              │
              ▼
   别人点链接落地 → 别人的 B1（闭环成立）
```

> **闭环关键澄清（原稿隐含、本版显式化）**
> 「发出的图 = 别人的 B1」在技术上不能只靠一张图片——微信/朋友圈里的图片本身不可点击跳转。
> 因此闭环真正成立的载体是「**图片 + 一条回流链接/二维码**」：
> - 线上分享：保存图片的同时，给用户一段可一起发出的文案，文案内含**回流链接**（点开即落到 B1）。
> - 卡面内嵌**二维码/短链**作为兜底（截图转发也能扫）。
> 没有这条链接/码，传播链路会断在「别人看到图但无处可测」。详见第 4 章与第 12 章。

### 2. 字段设计（屏 ①）

| 字段 | 必填/选填 | 交互 | 作用 |
|---|---|---|---|
| 性别 | 必答 | 点选 | 生成对应性别角色 |
| 出生日期 | 必填 | 日期选择器 | 命格感主锚点 |
| 出生时间 | 选填 | 点选 | 可跳过 |
| 出生地 | 选填 | 城市快捷选+搜索 | 城市级，不手打 |
| 球风题 | 必答 | 点选 | 埋「我以为 vs 系统判定」反差 |
| 位置题 | 选填 | 点选 | 可跳过 |
| 昵称 | 选填 | 保存图片时再问 | 卡片个性化 |

**必答三项**：性别、生日、球风。全程点选，无打字（昵称在保存时才问，且选填）。

### 3. 逐屏动线

#### 屏 A1 强钩子页（普通入口首屏）
- **谁/何时**：通过广告、主页、口口相传直接进入的新用户。
- **看到**：强钩子句、主视觉、2–3 个示例结果、「几步出结果」承诺。
- **可做**：点 CTA「测我的命格」。
- **去哪**：→ 屏 ①。
- **文案位**：主钩子句 / 示例结果名 ×2–3 / 承诺句 / CTA。

#### 屏 B1 朋友结果落地页（主力入口首屏）
- **谁/何时**：点了朋友分享的回流链接/二维码而来的「围观者」。
- **看到**：朋友的结果名 + 角色图、一句挑衅、CTA「测我的命格」。
- **不展示**：朋友的完整解读（解读留到围观者测出自己结果后才给，制造好奇）。
- **可做**：点 CTA。
- **去哪**：→ 屏 ①。
- **文案位**：挑衅/邀约句、CTA。

#### 屏 ① 输入流程
- **看到**：顶部轻提示、步骤指示、点选控件。
- **可做**：完成必答项；选填项可跳过。
- **去哪**：完成必答 → 屏 ②。
- **文案位**：顶部提示句 / 选填安抚句 / 球风题题干 / 位置题题干 / 按钮。

#### 屏 ② 揭晓动效
- **看到**：1.5–2.5s 动画、「正在分析」过场。
- **可做**：等待。
- **去哪**：自动 → 屏 ③。
- **文案位**：计算感过场句。

#### 屏 ③ 结果页
- **看到（第一屏）**：大结果名、角色图（含性别）、金句。
- **看到（下滑）**：展开解读、国家命格、**建议场上位置**（此字段同时供 Phase 2 排位复用）。
- **可做**：保存图片（主）；再测一次（次）；组一支队（预留位，Phase 2 点亮）。
- **去哪（按来源上下文分流）**：
  - 来自单人入口（A1/B1）→ 保存图片后进 **屏 ④ 传播**。
  - 来自拼队成员入口（屏 ⑧）→ 结果归入该队后进 **屏 ⑨ 加入成功页**（Phase 2，见第 8 章）。
  - 「再测一次」→ 回 屏 ①；「组一支队」→ 屏 ⑥（Phase 2）。
- **文案位**：结果名 / 金句 / 保存按钮 / 保存后引导句 / 次级动作按钮。

> **逻辑澄清**：屏 ③ 的「下一步」取决于**用户从哪条入口进来**。同一个结果页，单人用户走向「传播」，拼队成员走向「归队」。开发需在进入流程时携带「是否来自某球队」的上下文标识。

#### 屏 ④ 传播
- **看到**：保存成功确认 + 「去发给朋友」引导；卡面中部回流抓手（二维码/短链）。
- **可做**：切微信/小红书发图；系统已替用户备好「图 + 含回流链接的一句话」。
- **去哪**：别人点链接/扫码 → 别人的 B1（闭环）。
- **文案位**：可发群一句话（含回流链接）/ 卡面回流抓手。

### 4. 分享方式

| 方式 | 结论 |
|---|---|
| 保存图片 + 回流链接 | **主推（已确认）**。链接/二维码是闭环成立的硬条件，不可省。 |
| 一键发微信 | 加分项，非 MVP 前提。 |
| 一键发小红书 | 保存图 → 跳小红书 → 自己发，引导即可。 |
| 扫码 | 卡面二维码作为线下/跨设备/截图转发的兜底入口；线上主路径仍以链接为主。 |

## 6. Phase 1 必须为 Phase 2 预留的接口

Phase 1 开发时即落地，否则 Phase 2 需推翻重做：

> ⚠️ **最关键一项：结果持久化（Phase 2 命脉）**
> 拼队靠「球队链接归集成员结果」。每个成员点链接、测完后，其结果必须能被存下、归到某支队、供队长调出。
> Phase 1 哪怕无账号，也必须做掉「**结果存一份 + 给个唯一 ID**」。做成纯无状态 = Phase 2 不可能实现。
> 优先级：与单人主流程同级，不可砍。

| 预留项 | 要求 | 等级 |
|---|---|---|
| 结果可持久化 | 每次测完结果绑定唯一 ID 存下、之后可调出（即便无账号），供拼队归集 | **硬依赖·不可砍** |
| 结果带「建议位置/可排阵型」字段 | 每个命格结果附「建议场上位置」，否则无法排 11 人站位 | 硬依赖 |
| 角色形象可复用 | 角色立绘做成可单独抠出、可缩放，能排进合影队形，不写死在单人卡版式 | 硬依赖 |
| 「球队身份」可在无账号下找回 | 区分**队长管理链接**与**成员加入链接**；队长链接须能被本人持久找回（本地存/收藏/发到微信文件），否则关掉页面就丢了管理权 | **硬依赖**（本版新增，见第 12 章） |
| 结果页「组一支队」入口位 | UI 预留按钮位，Phase 1 不接功能，Phase 2 点亮 | 低成本预留 |

## Phase 2 · 拼队玩法

模型：队长发起 → 成员扫码/点链接加入并测 → 成员结果自动汇到队长 → 队长挑人排位 → 生成赛前 11 人合影。

合影形态：11 个命格角色穿统一队服、站赛前合影队形、每人标命格名 + 昵称。**非真人脸**（避开头像/肖像风险，复用单人角色素材）。

### 7. 拼队动线总览

```
【队长线】                          【成员线】
单人测完(屏③) 点「组一支队」          收到队长分享的「加入球队」链接
   ▼                                    ▼
屏⑥ 创建球队                        屏⑧ 成员落地页
 生成两类入口:                        「XX的球队已有N人,来占个位」
  · 队长管理链接(给自己,需收好)         │ 点「测我的命格并加入」
  · 成员加入链接(发给别人)             ▼
 自己作为第1名成员                  （走单人①②③,结果归入该队）
   │ 分享「成员加入链接」到群           ▼
   ▼                              屏⑨ 加入成功页
屏⑦ 球队管理页(队长专属)            「已加入,等队长发首发」
 实时看到所有加入者命格卡             (成员端结束,可再把加入链接转给别人)
 从N人挑11人+排位置+选阵型
   ▼
屏⑩ 生成赛前11人合影
 11个命格角色穿队服站位
 每人标命格名+昵称
   │ 保存合影
   ▼
 发回群 → 合影配文含「成员加入链接」
        → 第12、13人继续加入(闭环)
```

> **两类链接的区别（本版显式化，关键）**
> - **成员加入链接**：谁拿到都能加入，可无限转发；落到屏 ⑧。
> - **队长管理链接**：只有持有者能进屏 ⑦ 挑人/排位/成图，等价于「队长身份凭证」。在无账号模式下，必须引导队长把这条链接收好（自动存本地 + 提示「发到自己微信文件」），否则关掉页面就失去管理权。

### 8. 拼队逐屏动线

#### 屏 ⑥ 创建球队（队长）
- **进入**：从屏 ③「组一支队」。前提是该用户已完成单人测试，其结果即作为球队第 1 人。
- **看到**：球队名输入、生成的**成员加入链接/码**、「分享到群」按钮、**队长管理链接的保存引导**。
- **可做**：命名球队；分享成员加入链接；收好自己的队长管理链接。
- **去哪**：分享后 → 屏 ⑦。
- **文案位**：建队引导句 / 分享按钮 / 球队名占位提示 / 队长链接保存提示句。

#### 屏 ⑦ 球队管理页（队长专属）
- **进入**：屏 ⑥ 之后，或队长事后通过**队长管理链接**重新进入。
- **看到**：成员实时列表（每人命格卡，随加入增长）、已选/未选标记、阵型选择、当前已选人数 / 阵型所需人数。
- **可做**：从 N 人中挑 11 人；为每人排位置；选阵型；继续分享加入链接拉人。
- **校验**：选满 11 人且各位置数量匹配所选阵型，方可生成（防止站位空缺/重叠）。
- **去哪**：挑满并确认 → 屏 ⑩。
- **文案位**：成员列表空状态句 / 「再拉几人」催人句 / 生成按钮 / 未满员/阵型不匹配的提示句。

#### 屏 ⑧ 成员落地页（成员入口首屏）
- **谁/何时**：拿到「成员加入链接」点进来的人。
- **看到**：「XX 的球队已有 N 人」、已加入成员的命格预览、CTA「测我的命格并加入」。
- **可做**：点 CTA。
- **去哪**：→ 走单人流程（屏 ①②③，携带「来自该球队」上下文），结果归入该队 → 屏 ⑨。
- **文案位**：球队号召句（带人数，制造从众）/ CTA。

> **口径统一**：屏 ⑧ 强调「加入即进入候选池」，**是否首发由队长钦点**（屏 ⑦）。文案避免让人误以为「先到 = 必首发」；建议措辞为「来占个候选位，等队长点首发」。详见第 12 章。

#### 屏 ⑨ 加入成功页（成员）
- **看到**：「你已加入 XX 的球队」、自己的命格卡、等待提示。
- **可做**：把成员加入链接再转给别人；保存自己的单人卡（仍可走单人传播闭环）。
- **去哪**：转链接 → 别人的屏 ⑧（闭环）。
- **文案位**：加入确认句 / 「拉更多人」邀约句。

#### 屏 ⑩ 赛前 11 人合影（队长生成）
- **看到**：11 个命格角色穿队服站位、每人标命格名 + 昵称、阵型名、球队名。
- **可做**：保存合影；发回群。
- **去哪**：发回群（配文含成员加入链接）→ 成为新的「加入球队」入口。
- **文案位**：球队合影标题位 / 阵型名 / 保存与分享按钮 / 可发群一句话（含加入链接）。

### 9. 拼队设计要点
- **成员零负担**：只需点链接 → 测自己 → 自动归队，无需理解「球队」概念。
- **队长是唯一操作者**：挑人、排位、成图都在队长端，成员不协作。
- **球队链接 = 传播载体**：合影发群后加入链接仍在，第 12、13 人继续加入，比单人卡裂变更强。
- **合影放命格角色，非真人脸**。
- **无账号也能玩**：靠成员加入链接归集结果（依赖 Phase 1 的结果持久化预留）；队长靠管理链接保管身份。

## 10. 设计原则（贯穿两期）
- 每屏唯一主动作。
- 输入全程点选，昵称挪到保存后且选填。
- 结果先给后引导，不做分享解锁。
- B 线为主力，重点优化。
- 保存即传播起点，**且每次分享都带回流/加入链接**。
- B1 只给朋友结果 + 挑衅，解读留到自己结果页。
- 揭晓动效 1.5–2.5s。
- 一键发微信/小红书可降级。
- 性别必答，用于生成对应性别角色。
- Phase 1 即预留 Phase 2 接口。

## 12. 逻辑校验与待决项（本版新增）

本次逐屏走查后，确认**主干闭环逻辑是成立、合理的**：双入口合流、结果持久化作为 Phase 2 命脉、成员零负担归队、队长单点操作，这些设计自洽。下面是发现的**逻辑缺口/口径不一致**及处理建议，按优先级排列。

| # | 问题 | 原稿现状 | 风险 | 建议处理 |
|---|---|---|---|---|
